## 2. FEATURE SIGNATURE DEFINITION & DETERMINISTIC GROUPING

### 2.1 The 10 Approved Predictor Features
Grouping is computed strictly across the 10 features authorized in `shared/contracts/feature_contract.json`:
- **6 Numerical Features:** `Age`, `Academic Pressure`, `CGPA`, `Study Satisfaction`, `Work/Study Hours`, `Financial Stress`.
- **4 Categorical Features:** `Gender`, `Sleep Duration`, `Dietary Habits`, `Degree`.
- **Excluded Features:** `id`, `City`, `Profession`, `Work Pressure`, `Job Satisfaction`, `Family History of Mental Illness`, `Have you ever had suicidal thoughts ?`, and target `Depression`.

> [!IMPORTANT]
> The target variable `Depression` is **STRICTLY EXCLUDED** from group ID calculation. Group IDs represent input feature equivalence only.

### 2.2 Normalization & Precision Standards
To ensure identical input states produce bit-identical signatures regardless of runtime environment, floating-point representations, or string encoding, the following normalization rules are enforced:

1. **Numeric Precision Normalization:**
   - `Age`: Formatted as 2-decimal float (`f"{val:.2f}"`), e.g., `23.00`.
   - `Academic Pressure`: Formatted as 2-decimal float (`f"{val:.2f}"`), bounded in $[1.00, 5.00]$.
   - `CGPA`: Formatted as exact 2-decimal float (`f"{val:.2f}"`), bounded in $[0.00, 10.00]$.
   - `Study Satisfaction`: Formatted as 2-decimal float (`f"{val:.2f}"`), bounded in $[1.00, 5.00]$.
   - `Work/Study Hours`: Formatted as 2-decimal float (`f"{val:.2f}"`), bounded in $[0.00, 24.00]$.
   - `Financial Stress`: Formatted as 2-decimal float (`f"{val:.2f}"`) when present; mapped to `__MISSING__` when null or NaN.
2. **Categorical Normalization:**
   - Stripped of all leading and trailing whitespace.
   - Case-folded to lower case: `str(val).strip().lower()`.
   - Null, empty string, or whitespace-only values mapped to canonical token `__MISSING__`.
   - Unexpected categories: Validated against contract vocabulary; during signature generation, normalized as `str(val).strip().lower()`.
3. **Canonical Serialization & Hash Function:**
   - Features are serialized in a fixed lexicographical sequence:
     $$\text{sig\_str} = \text{Age} \parallel \text{AcadP} \parallel \text{CGPA} \parallel \text{StudySat} \parallel \text{WorkHrs} \parallel \text{FinStress} \parallel \text{Gender} \parallel \text{Sleep} \parallel \text{Diet} \parallel \text{Degree}$$
   - Key-value delimiter is `:` and feature delimiter is `|`.
   - Group ID is generated by computing the full 64-character SHA-256 digest of the UTF-8 encoded string:
     $$\text{group\_id} = \text{SHA256}(\text{sig\_str})$$
   - *Collision Check:* All $27,899$ unique raw feature tuples in Dataset A map 1-to-1 to $27,899$ distinct 64-character digests with zero hash collisions.

### 2.3 Mathematical Proof of Determinism & Group Audit
- **Determinism & Raw vs. Rounded Equivalence:** Formatting numeric values with `f"{val:.2f}"` preserves the native precision of the dataset (`CGPA` has at most 2 decimal places, while all other numeric inputs are integer ratings) while preventing IEEE 754 precision drift across platforms.
- **Empirical Execution on Dataset A ($N=27,901$):**
  * Total Unique Signatures: **$27,899$**.
  * Groups with Size 1: **$27,897$**.
  * Groups with Size 2: **$2$** (Group 1: `222742981b344bf1...`, Group 2: `6391c852d4d20154...`).
  * Groups with Size > 2: **$0$**.

## 3. GROUP-AWARE PARTITIONING STRATEGY

### 3.1 The Outer Development / Test Split (Holdout Vault)
To evaluate the final model, Dataset A must be divided into an $85\%$ Development Partition ($N \approx 23,715$) and a $15\%$ Test Vault ($N \approx 4,186$) while ensuring **zero group intersection**.

- **Why Row Counts Must Not Be Forcibly Fixed:** Forcing the test partition to contain exactly $4,186$ rows could require splitting a multi-row feature group across partition boundaries. Group integrity takes absolute precedence over exact row counts.
- **Partitioning Algorithm:** 
  To achieve an exact $15.0\%$ holdout while preserving stratification and group boundaries, a 20-fold `StratifiedGroupKFold(n_splits=20, shuffle=True, random_state=42)` is computed over the $27,899$ groups. 
  - Folds 0, 1, and 2 are combined to form the **Test Vault** ($3/20 = 15.0\%$).
  - Folds 3 through 19 are combined to form the **Development Partition** ($17/20 = 85.0\%$).
- **Expected Partition Distribution:**
  * **Test Vault:** **$4,185$ rows** ($14.999\%$), $4,184$ unique groups. Class balance: $58.57\%$ positive ($2,451$ Depressed / $1,734$ Non-Depressed).
  * **Development Partition:** **$23,716$ rows** ($85.001\%$), $23,715$ unique groups. Class balance: $58.55\%$ positive ($13,885$ Depressed / $9,831$ Non-Depressed).
  * **Group Intersection:** **$0$ groups** (Strict Zero Leakage).
  * **Duplicate Group Allocation:**
    - Group 1 (Rows 902 & 8257, conflicting labels): Allocated entirely to **Development**.
    - Group 2 (Rows 1818 & 11156, concordant labels): Allocated entirely to **Test Vault**.

### 3.2 Outer 5-Fold Cross-Validation on Development Data
Within the Development Partition ($N=23,716$), model development and comparison are governed by 5-fold outer cross-validation:
- **Algorithm:** `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)`.
- **Expected Outer Fold Distributions:**
  * Folds 1–4: $18,973$ Train rows / $4,743$ Validation rows.
  * Fold 5: $18,972$ Train rows / $4,744$ Validation rows.
  * Class Balance: Positive prevalence across all outer folds is $58.55\% \pm 0.01\%$.
  * Group Intersection: Exactly **$0$** across all 5 folds.
- **Handling Groups with Conflicting Labels in Outer CV:**
  * In `StratifiedGroupKFold`, groups are indivisible. Group 1 (both Row 902 and Row 8257) will reside in the training fold for 4 folds, and in the validation fold for 1 fold.
  * Conflicting labels are handled transparently: the algorithm balances class distributions at the fold level while guaranteeing that both records remain together.

## 4. NESTED GROUP-AWARE PROBABILITY CALIBRATION PROTOCOL

### 4.1 The Scikit-Learn API Limitation & Architectural Failure Mode
In standard Scikit-Learn pipelines, probability calibration is implemented via `CalibratedClassifierCV`. However, auditing `CalibratedClassifierCV` reveals critical group leakage failure modes:

1. **Failure Mode 1 (Integer CV):** Setting `cv=5` defaults to `StratifiedKFold(5)`. This ignores group identifiers entirely, causing identical feature vectors in training data to be split between calibration fitting and base estimator fitting.
2. **Failure Mode 2 (Group Splitter Object Exception):** Passing a group splitter object (e.g., `cv=StratifiedGroupKFold(5)`) to `CalibratedClassifierCV` and calling `.fit(X, y, groups=groups)` **fails with a fatal ValueError**:
   ```
   ValueError: Cannot have number of splits n_splits=5 greater than the number of groups: 1.
   ```
   *Root Cause:* `CalibratedClassifierCV.fit` does not accept `groups` in its parameter signature. When `check_cv` is called internally, `groups=None` is passed to `cv.split()`, which treats all rows as a single group.

### 4.2 The Verified Solution: Precomputed Inner Fold Generators
To guarantee group-isolated probability calibration without API failure or leakage, the outer training loop must precompute an explicit iterable of inner split indices and pass them directly to `CalibratedClassifierCV`:

```python
# Guaranteed Group-Aware Calibration Pattern:
inner_sgkf = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)
inner_cv_splits = list(inner_sgkf.split(X_outer_train, y_outer_train, groups=groups_outer_train))

calibrated_clf = CalibratedClassifierCV(
    estimator=base_pipeline,
    method="sigmoid", # or "isotonic"
    cv=inner_cv_splits # Explicit pre-split iterable enforces group isolation
)
calibrated_clf.fit(X_outer_train, y_outer_train)
```

### 4.3 Step-by-Step Nested Evaluation Procedure (Per Outer Fold)
For each of the 5 outer folds:
1. **Outer Isolation:** Extract `(X_train, y_train, groups_train)` and `(X_val, y_val, groups_val)`. `(X_val, y_val)` is locked and untouched.
2. **Pipeline Preprocessing Isolation:** Fit `ColumnTransformer` (imputation + scaling + encoding) strictly on `X_train`. Never fit on `X_val`.
3. **Inner Group-Aware Splitting:** Generate 5 inner fold splits strictly within `(X_train, y_train)` using `StratifiedGroupKFold(5, groups=groups_train)`.
4. **Calibrated Fitting:** Fit `CalibratedClassifierCV` using the inner precomputed splits. Across each inner fold:
   - Base estimator is fitted on $4/5$ of outer training data.
   - Platt calibrator (or Isotonic regressor) is fitted on $1/5$ of outer training data.
   - No inner fold shares feature groups between base model training and probability calibration.
5. **Untouched Validation Inference:** Transform `X_val` using the fitted preprocessor and generate calibrated probabilities: $p_{\text{val}} = \text{calibrated\_clf.predict\_proba}(X_{\text{val}})[:, 1]$.
6. **Metric Computation:** Compute Discrimination (ROC-AUC, PR-AUC), Classification (Accuracy, Balanced Acc, Precision, Recall, F1), and Calibration (Brier, ECE, Slope, Intercept).

## 5. FINAL TEST VAULT GOVERNANCE & UNCERTAINTY QUANTIFICATION

### 5.1 Test Vault Rules
The Test Vault ($N=4,185$ rows, $15.0\%$) is governed by strict anti-overfitting controls:
1. **Zero Access During Development:** No candidate model architecture (Logistic Regression, Random Forest, XGBoost) may be selected using Test Vault metrics.
2. **Zero Hyperparameter Tuning:** No grid searches, learning rate adjustments, or depth selections may reference Test Vault outcomes.
3. **Zero Threshold Optimization:** The decision threshold ($0.50$) is fixed prior to Test Vault evaluation.
4. **Single-Shot Final Evaluation:** The single best candidate model selected from outer 5-fold cross-validation is evaluated exactly once on the Test Vault.
5. **Cryptographic Record:** When Stage 3B is authorized, the exact array of Test Vault row indices and their SHA-256 hash digest must be recorded in `experiments/registry.json`.

### 5.2 Proposed Uncertainty Quantification via Group-Level Bootstrap
- **Proposed Protocol (Not an Executed Experiment):**
  * When Stage 3B is authorized, uncertainty quantification will be evaluated via a proposed $1,000$-iteration Group-Level Bootstrap with master seed pinned to $42$.
  * Resampling unit: The unique feature group $g \in \{1, 2, \dots, G\}$.
  * Entire groups and all their associated rows and observed labels are sampled together with replacement.
  * Stratification: Stratified at the group level by the majority target label.
- **Test-Vault Cluster Structure:**
  * The Test Vault comprises **$4,184$ unique groups** containing $4,185$ rows.
  * Cluster breakdown: **$4,183$ singleton groups (size 1)** and **$1$ two-row group (Group 2, size 2, $y=1, y=1$)**.
- **Empirical Status of Group vs. Row Bootstrap Impact:**
  * The actual quantitative impact of group-level vs. row-level resampling on confidence interval bounds **has not yet been measured**, because no experimental bootstrap has been executed during Stage 3A.
  * No unmeasured claims of asymptotic convergence or negligible practical differences are assumed. Group-level resampling is retained strictly as the mathematically appropriate proposed specification to preserve cluster exchangeability.
- **Handling Conflicting-Label Groups:** If Group 1 is drawn in any development-fold bootstrap iteration, both discordant rows enter the resample together, naturally propagating label inconsistency into metric distributions.

## 6. CONFLICTING-LABEL SENSITIVITY ANALYSIS (GROUP 1)

### 6.1 Group 1 Profile & Ground Truth Ambiguity
Group 1 consists of two records with identical 10-feature profiles:
- **Row 902:** `id: 4657`, `Age: 23`, `Academic Pressure: 2.0`, `CGPA: 8.04`, `Study Satisfaction: 4.0`, `Work/Study Hours: 8.0`, `Financial Stress: 1.0`, `Gender: Male`, `Sleep: Less than 5 hours`, `Diet: Moderate`, `Degree: B.Tech`.  
  *Label:* **`Depression = 1`** (Respondent reported suicidal ideation: `Yes`, City: `Meerut`).
- **Row 8257:** `id: 41608`, identical 10 features.  
  *Label:* **`Depression = 0`** (Respondent reported suicidal ideation: `No`, City: `Ludhiana`).

### 6.2 Primary vs. Sensitivity Protocol
- **Primary Analysis Protocol:**
  * Both records are retained in the Development Partition within the same group.
  * Neither record is deleted, relabeled, or merged.
  * The duplicate feature signature has conflicting observed labels. This demonstrates label inconsistency in the dataset but does not establish the population-level conditional probability or Bayes error.
- **Sensitivity Analysis Protocol:**
  * Candidate models will be evaluated in a secondary benchmark with the entire Group 1 (both rows 902 and 8257) excluded from the dataset ($N=23,714$ in Dev).
  * Delta metrics will be computed:
    $$\Delta M = M_{\text{primary}} - M_{\text{excluded}}$$
  * If $|\Delta \text{ROC-AUC}| < 0.001$ and $|\Delta \text{Brier}| < 0.001$, it confirms that Group 1 does not exert disproportionate leverage on decision boundaries or calibration parameters.
  * Primary and sensitivity results will be published in separate, non-conflated report tables.

## 7. TWO-COHORT POLICY & COMPARATIVE METHODOLOGY

### 7.1 Defined Cohorts
1. **Historical-Reproduction Cohort ($N=27,901$):** Full dataset with `Profession` dropped, preserving all 31 non-student records (Architect, Doctor, Teacher, etc., with $90.3\%$ depression rate).
2. **Student-Focused Engineering Cohort ($N=27,870$):** Filtered strictly to rows where `Profession == 'Student'`.

### 7.2 Group Invariance & Post-Filter Partitioning
- **Group ID Invariance:** Because the grouping function operates exclusively on the 10 features, individual group IDs are immutable. Filtering out the 31 non-students removes 31 unique groups (none of which belong to Group 1 or Group 2).
- **Post-Filter Re-Partitioning:** Group-aware partitioning (`StratifiedGroupKFold`) must be executed independently on each cohort to preserve exact fold stratification:
  * Historical Cohort: $27,899$ groups $\rightarrow$ $4,185$ Test / $23,716$ Dev.
  * Student Cohort: $27,868$ groups $\rightarrow$ $4,180$ Test / $23,690$ Dev.
- **Comparative Scientific Standard:**
  * The two cohorts must **NOT** be reported as "independent external validation cohorts."
  * The Student Cohort is a nested $99.89\%$ subset of the Historical Cohort.
  * Differences between the cohorts represent a **domain contamination sensitivity analysis**, measuring whether non-student records distort student calibration or false-positive rates.

## 8. COMPLETE ALGORITHMIC PSEUDOCODE (NESTED GROUP-AWARE CV)

```python
"""
ALGORITHMIC SPECIFICATION ONLY — DO NOT EXECUTE DURING STAGE 3A
Nested Group-Aware Cross-Validation and Fold-Isolated Calibration Protocol
"""

def stage_3b_nested_group_aware_evaluation(dataset_df, feature_cols, target_col, cohort_name):
    # 1. Generate Deterministic Feature Signatures
    groups = compute_deterministic_signatures(dataset_df[feature_cols])
    y = dataset_df[target_col].values
    X = dataset_df[feature_cols]

    # 2. Outer Holdout Vault Partition (20-fold StratifiedGroupKFold, 3 folds = 15%)
    outer_holdout_splitter = StratifiedGroupKFold(n_splits=20, shuffle=True, random_state=42)
    holdout_splits = list(outer_holdout_splitter.split(X, y, groups=groups))
    
    test_vault_indices = concat([holdout_splits[0][1], holdout_splits[1][1], holdout_splits[2][1]])
    dev_indices = [idx for idx in range(len(dataset_df)) if idx not in set(test_vault_indices)]
    
    X_dev, y_dev, groups_dev = X.iloc[dev_indices], y[dev_indices], groups.iloc[dev_indices]
    X_test_vault, y_test_vault = X.iloc[test_vault_indices], y[test_vault_indices]
    
    # Assert zero group leakage into test vault
    assert len(set(groups_dev).intersection(set(groups.iloc[test_vault_indices]))) == 0

    # 3. Outer 5-Fold Cross-Validation on Development Partition
    outer_cv = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)
    outer_fold_metrics = []

    for fold_idx, (train_idx, val_idx) in enumerate(outer_cv.split(X_dev, y_dev, groups=groups_dev)):
        # Isolate outer training and validation folds
        X_outer_train, y_outer_train = X_dev.iloc[train_idx], y_dev[train_idx]
        groups_outer_train = groups_dev.iloc[train_idx]
        
        X_outer_val, y_outer_val = X_dev.iloc[val_idx], y_dev[val_idx]
        groups_outer_val = groups_dev.iloc[val_idx]

        # Verify zero group leakage between outer train and validation
        assert len(set(groups_outer_train).intersection(set(groups_outer_val))) == 0

        # Define candidate base pipeline
        base_pipeline = build_candidate_pipeline(feature_cols)

        # 4. Nested Group-Aware Calibration
        # Precompute inner splits to bypass Scikit-Learn API groups limitation
        inner_cv = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)
        inner_splits = list(inner_cv.split(X_outer_train, y_outer_train, groups=groups_outer_train))

        calibrated_model = CalibratedClassifierCV(
            estimator=base_pipeline,
            method="sigmoid", # Platt scaling
            cv=inner_splits    # Precomputed index pairs guarantee inner group isolation
        )

        # Fit strictly on outer training data (base model + calibrator)
        calibrated_model.fit(X_outer_train, y_outer_train)

        # 5. Untouched Outer Validation Inference
        val_probs = calibrated_model.predict_proba(X_outer_val)[:, 1]
        val_preds = (val_probs >= 0.50).astype(int)

        # 6. Record Comprehensive Metrics
        fold_eval = evaluate_fold_metrics(y_outer_val, val_preds, val_probs)
        outer_fold_metrics.append(fold_eval)

    # 7. Aggregate Outer Cross-Validation Performance
    mean_dev_metrics = aggregate_metrics(outer_fold_metrics)
    
    # 8. Single-Shot Test Vault Evaluation (Final Selected Model Only)
    # Fit final pipeline on 100% of Development Data using Dev group splits for calibration
    final_inner_splits = list(StratifiedGroupKFold(5, shuffle=True, random_state=42).split(X_dev, y_dev, groups=groups_dev))
    final_model = CalibratedClassifierCV(estimator=base_pipeline, method="sigmoid", cv=final_inner_splits)
    final_model.fit(X_dev, y_dev)

    test_vault_probs = final_model.predict_proba(X_test_vault)[:, 1]
    final_vault_metrics = evaluate_fold_metrics(y_test_vault, (test_vault_probs >= 0.5).astype(int), test_vault_probs)
    bootstrap_cis = compute_bootstrap_cis(y_test_vault, test_vault_probs, n_bootstraps=1000, seed=42)

    return {
        "cohort": cohort_name,
        "dev_cv_metrics": mean_dev_metrics,
        "test_vault_metrics": final_vault_metrics,
        "bootstrap_cis": bootstrap_cis
    }
```
